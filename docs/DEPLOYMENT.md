# Configuration and operating guide

## Current local setup

AURA runs in Docker at http://localhost:5273, with API documentation at http://localhost:8200/docs. PostgreSQL and Ollama use persistent volumes. The optional local observability stack runs Langfuse at http://localhost:3300. All published ports are restricted to the local machine.

No OpenAI/Anthropic/Gemini key, cloud database, paid judge, or paid monitoring account is required. Public Sentence Transformer models download from Hugging Face without a paid API. The installed small Ollama model tests the pipeline; choose a model appropriate for your hardware and evaluate it before relying on it.

## Environment settings

| Variable | Purpose | What the user needs to do |
|---|---|---|
| `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD` | Application database | Generated/defaulted for local setup. Do not casually change credentials on an existing persistent database. |
| `DATABASE_URL` | Connection for host Python development | Match database credentials and host port 5433. Compose supplies its own internal URL. |
| `OLLAMA_BASE_URL` | Host Python inference endpoint | Normally http://localhost:11434. Compose supplies http://ollama:11434 internally. |
| `FRONTEND_PORT`, `BACKEND_PORT`, `POSTGRES_PORT`, `OLLAMA_PORT` | Published ports | Defaults 5273, 8200, 5433, 11434. Change only to resolve a conflict; restart the affected services. |
| `API_KEY` | Optional shared-workspace API authentication | Blank in local development. If set, enter it in AURA Settings; scripts can read it from the environment. This is not a paid-provider key. |
| `WEBHOOK_SECRET` | Authenticate incoming failure events | Generated by configure-local.py. External clients send `Authorization: Bearer <secret>`. Do not use the workspace key instead. |
| `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` | Local telemetry project | Generated and initialized automatically with `--observability`. Keep the secret key private. |
| `LANGFUSE_BASE_URL` | SDK telemetry destination | http://langfuse-web:3000 inside Docker. Host development needs http://localhost:3300 instead. |
| `OTEL_ENDPOINT` | OTLP HTTP trace receiver | http://otel:4318/v1/traces inside the optional Docker network. Leave blank when no collector is used. |
| `LF_ADMIN_PASSWORD` | Langfuse browser account password | Read from your private .env. Username/email: developer@aura.local. |
| `LF_DATABASE_PASSWORD`, `LF_REDIS_PASSWORD`, `LF_STORAGE_PASSWORD`, `LF_CLICKHOUSE_PASSWORD`, `LF_SALT`, `LF_ENCRYPTION_KEY`, `LF_NEXTAUTH_SECRET` | Internal observability secrets | Generated automatically. Preserve these values with their data volumes. |

The application also supports server-side `EMBEDDING_MODEL`, `RERANKER_MODEL`, `OLLAMA_TIMEOUT_SECONDS`, and `REQUEST_LIMIT_PER_MINUTE` settings. The default embedding model is 384-dimensional; changing it requires compatible dimensions and reindexing. These settings require a Compose environment override when using Docker; merely adding an unreferenced key to the root .env does not pass it into a container.

## Start/restart

From the repository root:

```sh
python3 scripts/configure-local.py --observability
python3 scripts/docker-up.py --observability
```

The configure command preserves existing secrets. The Docker helper stages readable source files without macOS resource metadata, builds images, runs migrations, and starts services. It does not remove stored data.

For a core-only fresh setup, omit `--observability` from both commands. If an existing .env has telemetry enabled but you intentionally stop the observability services, clear `OTEL_ENDPOINT`, `LANGFUSE_PUBLIC_KEY`, and `LANGFUSE_SECRET_KEY`, then recreate the backend. Disabling export does not delete local traces.

## Health and logs

```sh
docker compose ps
curl http://localhost:8200/api/v1/health
docker compose logs --tail=100 backend
docker compose logs --tail=100 ollama
```

For optional services:

```sh
docker compose -f docker-compose.yml -f docker-compose.observability.yml --profile observability ps
```

## Common issues

- **No models:** run `docker compose exec ollama ollama pull qwen2.5:0.5b`, then refresh models in Settings/Playground. Pulling a model is an explicit download.
- **No vector results:** index documents first or choose BM25. A scanned PDF may need OCR before upload.
- **Cold start:** model download/loading can take time. Embeddings and optional reranking models download on first use and persist in a named volume.
- **401 API response:** the server has API_KEY enabled. Apply the same key in Settings for that browser session. Webhook authentication uses WEBHOOK_SECRET separately.
- **Webhook 503:** configure WEBHOOK_SECRET and recreate the backend. Webhook 409 means an event ID was reused with different content.
- **Baseline failure despite good outputs:** inspect the gate reason. Different run modes or changed cases are not comparable to the saved baseline.
- **Judge is unscored:** inspect its stored error and source trace. Model output can fail validation; AURA does not fabricate a fallback score.
- **Security failures:** inspect actual responses. The tiny model can reveal synthetic secrets or ignore output rules. A failing test is an observed result, not a reason to mark the test passed.
- **External-drive Docker/xattr errors:** use scripts/docker-up.py rather than building directly from ExFAT.
- **Port conflict:** adjust the corresponding published port in .env and use the new URL. Internal Docker service ports remain unchanged.

## Backups

Database data and model caches live in Docker volumes. `docker compose down` preserves them; do not add `-v` unless you intend to discard data. Take backups before migration, credential rotation, or machine changes.

```sh
mkdir -p backups
docker compose exec -T db pg_dump -U aura -d aura -Fc > backups/aura.dump
```

Adapt the username/database if customized. Treat backups as private: they include prompts, responses, contexts, review names, and failure content. The `.env` file is also needed to recover the observability stack's encrypted configuration. The backup directory is ignored by Git.

## Deployment boundary

This version is a functional local, single-workspace platform. It has request limits, optional shared API authentication, a separately authenticated webhook, bounded tool execution, and an unprivileged backend container. It does not implement multi-tenant access control or authenticated individual reviewer identities. Batches are synchronous; interruption can leave a failed/incomplete run rather than a resumable distributed job.

Before public/team deployment, add an identity provider and project authorization, a durable job queue with cancellation/recovery, tested backups/restores, TLS/reverse-proxy policy, secrets management, and retention/access auditing suited to your data. Set repository branch protection to require the relevant CI quality gates. Terraform examples are validated but no infrastructure is applied automatically.
